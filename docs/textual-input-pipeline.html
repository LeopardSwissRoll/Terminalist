02Windows 드라이버 상세

콘솔 모드 설정

Textual이 Windows에서 시작할 때 가장 먼저 하는 일입니다.

# win32.py:158-180 — enable_application_mode()

# stdin: VT 입력 모드 활성화
# → Windows가 키 입력을 VT100 이스케이프 시퀀스로 변환
set_console_mode(terminal_in, ENABLE_VIRTUAL_TERMINAL_INPUT)  # 0x0200

# stdout: VT 출력 처리 활성화
# → ANSI 이스케이프 시퀀스를 해석해서 출력
set_console_mode(terminal_out, current | ENABLE_VIRTUAL_TERMINAL_PROCESSING)
핵심 주의점

stdin에 ENABLE_VIRTUAL_TERMINAL_INPUT을 설정할 때 기존 모드를 OR 하지 않고 덮어씁니다. 즉 ENABLE_PROCESSED_INPUT, ENABLE_LINE_INPUT 등이 모두 꺼집니다. 이것은 raw 모드 진입을 위한 의도된 동작입니다.

EventMonitor — 입력 읽기 스레드

# win32.py:228-292 — EventMonitor.run()

while not exit_requested():
    # 1. 타임아웃된 시퀀스 방출
    for event in parser.tick():
        self.process_event(event)

    # 2. Win32 API로 콘솔 이벤트 대기 (100ms 타임아웃)
    if wait_for_handles([hIn], 100) is None:
        continue

    # 3. ReadConsoleInputW()로 INPUT_RECORD 배열 읽기
    ReadConsoleInputW(hIn, byref(input_records), MAX_EVENTS, byref(read_count))

    for input_record in read_input_records:
        if event_type == KEY_EVENT:
            key_event = input_record.Event.KeyEvent
            key = key_event.uChar.UnicodeChar

            if key_event.bKeyDown:
                # ★ 수식키 단독 입력 필터링
                if key_event.dwControlKeyState and key_event.wVirtualKeyCode == 0:
                    continue
                append_key(key)

    if keys:
        # 4. UTF-16 서로게이트 페어 처리 (이슈 #3178)
        data = "".join(keys).encode("utf-16", "surrogatepass").decode("utf-16")
        for event in parser.feed(data):
            self.process_event(event)

실제 Ctrl+A 키 입력 시 경로

1
사용자가 Ctrl+A를 누름
Windows Console이 KEY_EVENT_RECORD를 생성합니다.
2
KEY_EVENT_RECORD 필드값
bKeyDown = True
wVirtualKeyCode = 0x41 (= 'A')
dwControlKeyState = LEFT_CTRL_PRESSED
uChar.UnicodeChar = '\x01'
3
필터 통과
wVirtualKeyCode == 0x41 != 0 이므로 필터에 걸리지 않음. '\x01'이 keys에 추가됩니다.
4
XTermParser.feed('\x01')
ANSI_SEQUENCES_KEYS['\x01'] → (Keys.ControlA,)
→ events.Key("ctrl+a", '\x01') 이벤트 생성

03XTermParser 파서

Generator 기반 비동기 파서입니다. read1(timeout)으로 한 문자씩 읽으며 이스케이프 시퀀스를 조립합니다.

파싱 전략

def parse(self, token_callback):
    while not self.is_eof:
        character = yield read1()

        if character != ESC:
            # 비-ESC 문자 → 즉시 키 이벤트
            for event in sequence_to_key_events(character):
                on_key_token(event)
            continue

        # ESC로 시작 → 이스케이프 시퀀스일 수 있음
        sequence = ESC
        while True:
            try:
                new_char = yield read1(ESCAPE_DELAY)  # 0.1초 타임아웃
            except ParseTimeout:
                # 타임아웃 → 단독 ESC 키
                send_sequence()
                break

            sequence += new_char
            # 시퀀스 매칭 시도 (최대 32자)
            key_events = list(sequence_to_key_events(sequence))
            if key_events:
                for event in key_events:
                    on_key_token(event)
                break

3단계 키 매칭 (_sequence_to_key_events)

1
Kitty 프로토콜 (현대적)
정규식: \x1b\[(?:(\d+)(?:;(\d+))?)?([u~ABCDEFHPQRS])
예: \x1b[97;5u → number=97(='a'), modifiers=5(ctrl), end='u'
→ "ctrl+a"
2
ANSI 시퀀스 테이블 (레거시)
ANSI_SEQUENCES_KEYS 딕셔너리에서 직접 매칭.
예: \x01 → Keys.ControlA,   \x1b[1;5A → Keys.ControlUp
3
단일 문자 처리 (폴백)
unicodedata.name()으로 문자 이름 조회.
예: 'a' → "a",   '/' → "solidus"

Kitty 프로토콜이 해결하는 것

Kitty 프로토콜(\x1b[>1u)이 활성화되면 모든 키에 고유한 시퀀스가 부여됩니다:

키레거시Kitty 프로토콜구분 가능?
Ctrl+A \x01 \x1b[97;5u 둘 다 가능
Ctrl+I \x09 (= Tab) \x1b[105;5u Kitty만 가능!
Tab \x09 (= Ctrl+I) \x1b[9u Kitty만 가능!
Ctrl+M \x0d (= Enter) \x1b[109;5u Kitty만 가능!
BUT: 지원 여부가 핵심

Textual은 \x1b[>1u를 보내서 Kitty 프로토콜 활성화를 시도하지만, 터미널이 지원하지 않으면 무시됩니다. VSCode 터미널(xterm.js 기반)은 현재 미지원.

05키 이벤트 디스패치

dispatch_key — 핸들러 탐색

# _dispatch_key.py
async def dispatch_key(node: DOMNode, event: events.Key) -> bool:
    # event.name_aliases에서 모든 별명 시도
    # 예: "ctrl+i" → ["ctrl+i", "tab"]
    for key_method_name in event.name_aliases:
        # key_ctrl_i() 또는 key_tab() 탐색
        key_method = getattr(node, f"key_{key_method_name}", None)
        if key_method:
            handled = (await invoke(key_method, event)) is not False

바인딩 해석 순서

  1. 포커스된 위젯의 바인딩
  2. 부모 위젯들의 바인딩 (버블링)
  3. Screen의 바인딩
  4. App의 바인딩
  5. priority=True인 바인딩이 항상 우선

실제 바인딩 예시

from textual.app import App
from textual.binding import Binding

class TermApp(App):
    BINDINGS = [
        # 단일 키
        Binding("q", "quit", "종료"),

        # 수식키 조합
        Binding("ctrl+b", "prefix", "Prefix", priority=True),

        # 복합 키 (쉼표로 구분 → 두 바인딩 생성)
        Binding("j,down", "cursor_down", "아래"),

        # ID 기반 (키맵으로 오버라이드 가능)
        Binding("ctrl+s", "save", "저장", id="save"),
    ]

# 포맷: \x1b[<buttons;x;yM (누름) 또는 \x1b[<buttons;x;ym (뗌)

# buttons 비트필드:
# bit 0-1: 버튼 번호 (0=왼쪽, 1=가운데, 2=오른쪽)

# bit 4:   Ctrl 누름
# bit 5:   이동 중 (mouse move)

Kitty 수식키 비트 인코딩

# modifier_bits = int(modifiers) - 1
#
# bit 0 = Shift     (1)
# bit 1 = Alt       (2)
# bit 2 = Ctrl      (4)
# bit 3 = Super     (8)
# bit 4 = Hyper     (16)
# bit 5 = Meta      (32)
#
# 예: Ctrl+Shift+A
# → \x1b[97;6u  (modifiers = 1 + Shift(1) + Ctrl(4) = 6)
# → key_tokens = ["ctrl", "shift", "a"]
# → event name = "ctrl+shift+a"

08Windows 환경 입력 문제 분석

문제 1: Kitty 프로토콜 미지원 터미널

VSCode 터미널

VSCode의 통합 터미널은 xterm.js 기반입니다. \x1b[>1u를 보내도 무시됩니다. Ctrl+키는 레거시 컨트롤 문자(\x01~\x1a)로만 전달됩니다.

문제 2: VSCode 키 가로채기

VSCode가 일부 Ctrl+키 조합을 자체 단축키로 가로채서 터미널까지 전달하지 않습니다:

  • Ctrl+K — VSCode 복합 단축키 prefix
  • Ctrl+Shift+P — Command Palette
  • Ctrl+` — 터미널 토글
  • Ctrl+Shift+~ — 새 터미널

terminal.integrated.commandsToSkipShell 설정으로 일부 조정 가능.

문제 3: ESC 타이밍

# _xterm_parser.py:232
new_character = yield read1(ESCAPE_DELAY)  # 기본 0.1초

네트워크 지연이 있는 환경이나 느린 터미널에서 이스케이프 시퀀스가 쪼개져 도착하면, 시퀀스를 ESC + 개별 문자들로 잘못 해석할 수 있습니다.

문제 4: Windows ESC 이중 전송

# _ansi_sequences.py:51-53
"\x1b\x1b": (Keys.Escape,)
# Windows가 ESC를 한 번 누르면 \x1b\x1b를 보내는 경우
# → Textual은 이것을 단일 ESC로 처리

문제 5: EventMonitor 필터

# win32.py:273-277
if key_event.dwControlKeyState and key_event.wVirtualKeyCode == 0:
    continue  # 수식키 단독 입력 무시

이 필터의 의도는 Ctrl/Alt/Shift 단독 입력을 무시하는 것이지만, 일부 특수 입력이나 IME에서 오탐 가능성이 있습니다.

10Terminalist에서의 함의

이중 키 처리 문제

Terminalist는 Textual 앱 안에서 PTY 터미널을 호스팅합니다. 키 입력 경로가 이중 구조입니다:

사용자 키 → Windows Console → Textual 앱 → (PTY로 전달) Textual이 \x1b[>1u (Kitty) 활성화 시도 │ ├─ 호스트 터미널이 지원하면 → Kitty 시퀀스로 입력 수신 └─ 호스트 터미널이 미지원이면 → 레거시 컨트롤 문자로 폴백 Ctrl+B를 prefix key로 쓰려면: → Textual이 먼저 가로채야 함 (on_key에서 event.stop()) → 나머지 키는 PTY로 VT100 시퀀스 변환해서 전달 → 이미 tui/vt100.py에서 Key → VT100 변환 구현

권장 사항

체크리스트
  1. Kitty 프로토콜 지원 여부 감지 — \x1b[?u 쿼리 후 응답 확인
  2. 레거시 폴백 경로 항상 유지 — \x01~\x1a 컨트롤 문자 기반
  3. Prefix 키 처리는 Textual 이벤트 레벨에서 — on_key()에서 가로채기
  4. PTY 전달 시 VT100 매핑 — Textual Key → VT100 바이트 변환
  5. VSCode에서 테스트 필수 — Kitty 미지원이므로 레거시 경로만 동작

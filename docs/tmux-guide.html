01 What is tmux

tmux (terminal multiplexer) is a program that enables multiple terminal sessions to be created, accessed, and controlled from a single screen. tmux may be detached from a screen and continue running in the background, then later reattached. It was created by Nicholas Marriott and first appeared in OpenBSD 4.6 (released October 2009), though development began in 2007.

Origin and Purpose

tmux was written as a modern, BSD-licensed replacement for GNU Screen, which had been the dominant terminal multiplexer since 1987. Marriott created tmux because GNU Screen had accumulated decades of legacy code, had a GPL license that was incompatible with the BSD ecosystem, and lacked modern features like a clean client-server architecture.

tmux was designed from the ground up with a proper client-server model, a consistent command interface, and scriptability as core principles. It was developed as part of the OpenBSD project, reflecting that project's emphasis on code correctness, clean design, and permissive licensing.

Platform Support

tmux runs on OpenBSD, FreeBSD, NetBSD, Linux, macOS, and Solaris. It depends on libevent 2.x and ncurses, and requires a C compiler, make, pkg-config, and yacc/bison to build from source.

Key Characteristics

  • Persistent sessions -- survive disconnects, SSH timeouts, and intentional detachment
  • Multiple windows and panes -- split a single terminal into many
  • Client-server architecture -- many clients can attach to the same session
  • Scriptable -- every action has a corresponding command
  • Highly configurable -- keybindings, status bar, colors, behavior all customizable
  • Copy mode -- scroll back, search, and copy text from any pane

02 Core Concepts & Architecture

The Hierarchy: Server > Sessions > Windows > Panes

tmux organizes everything in a strict nesting hierarchy. Understanding this is fundamental to using tmux effectively.

tmux Server (single process, manages everything) | +-- Session "development" (named group of windows) | +-- Window 0: "editor" (like a tab) | | +-- Pane 0: vim (terminal split) | | +-- Pane 1: terminal (terminal split) | +-- Window 1: "server" | | +-- Pane 0: ssh logs | +-- Window 2: "database" | +-- Pane 0: psql | +-- Session "monitoring" | +-- Window 0: "htop" | +-- Window 1: "logs" | +-- Pane 0: tail -f app.log | +-- Pane 1: tail -f error.log | +-- Client (your terminal) ----attached to----> Session "development" +-- Client (colleague's terminal) --attached to--> Session "development"

Server

The tmux server is a single background process that manages all sessions, windows, and panes. When you first run tmux, a server is automatically started. The server and each client are separate processes which communicate through a Unix domain socket in /tmp (or the directory set by TMUX_TMPDIR). The default socket is named default.

You can run multiple independent tmux servers using different socket names with tmux -L socket-name. The server continues running as long as there are active sessions (unless exit-empty is off). Once all sessions are killed, the server exits.

Sessions

A session is a named collection of windows managed by the server. Sessions are the top-level organizational unit. Key facts:

  • Each session has a name (auto-assigned as 0, 1, 2... or manually named)
  • A session has one or more windows
  • Sessions are persistent -- they survive client disconnects
  • Multiple clients can attach to the same session simultaneously (pair programming)
  • Sessions can be grouped -- sessions in the same group share windows

Windows

A window occupies the entire screen (like a tab in a web browser). Key facts:

  • Windows are numbered starting from 0 (configurable with base-index)
  • Each window has a name (defaults to the running program, or can be set manually)
  • Windows can be linked to multiple sessions
  • Each window contains one or more panes
  • The current window is marked with * in the status bar, the last-used with -

Panes

A pane is a rectangular area within a window, each containing a separate pseudo terminal (pty). Key facts:

  • Panes are splits within a window -- horizontal or vertical
  • Panes are numbered beginning from zero in the order they are created
  • Each pane runs its own independent shell or program
  • Panes can be zoomed to temporarily fill the whole window
  • Panes can be broken out into their own window
  • Panes can be swapped, rotated, and resized

Clients

A client is the terminal (your terminal emulator) that is attached to a session to interact with it. Multiple clients can connect to the same session simultaneously. Clients can be read-only, have independent active panes, or be in control mode (for programmatic interaction).

Key Insight

The separation between server and client is what makes tmux's killer feature possible: you can detach your client (closing your terminal or losing SSH connection), and the server keeps all your sessions running. When you reconnect, you simply reattach and everything is exactly as you left it.

03 Getting Started

Installation

# Ubuntu / Debian
sudo apt install tmux

# macOS (Homebrew)
brew install tmux

# Fedora / RHEL
sudo dnf install tmux

# Arch Linux
sudo pacman -S tmux

# From source (requires libevent, ncurses, C compiler, make, pkg-config, yacc)
git clone https://github.com/tmux/tmux.git
cd tmux
sh autogen.sh
./configure && make
sudo make install

First Session

# Start tmux (creates a new session)
tmux

# Start with a named session
tmux new-session -s myproject

# Short form
tmux new -s myproject

When tmux starts, it creates a new session with a single window and displays it on screen. A status line at the bottom shows the current session name, window list, and time. You interact with tmux by pressing the prefix key (Ctrl+B by default) followed by a command key.

The Prefix Key Concept

Because tmux sits between you and your terminal programs, it needs a way to distinguish between keys meant for tmux and keys meant for the program running inside a pane. This is the purpose of the prefix key:

  1. Press Ctrl+B (the prefix) -- nothing visible happens yet
  2. Release, then press the command key (e.g., c to create a new window)
  3. tmux intercepts this combination and performs the action
Tip

Many users remap the prefix to Ctrl+A (like GNU Screen) because it is easier to reach. Add to ~/.tmux.conf:
set -g prefix C-a
unbind C-b
bind C-a send-prefix

05 Copy Mode & Scrollback

Copy mode allows you to scroll through a pane's history (scrollback buffer), search for text, select text, and copy it to a paste buffer. This is one of tmux's most powerful features -- every pane maintains a configurable history of output (default 2000 lines, set with history-limit).

Entering and Exiting Copy Mode

  • Enter: Ctrl+B then [
  • Also enters on: Ctrl+B then Page Up (enters and scrolls up one page)
  • Exit: q (vi mode) or Escape (emacs mode)

A position indicator appears in the top-right corner showing the current line position and the total number of lines in the history buffer.

Key Mode: emacs vs vi

Copy mode uses one of two key tables depending on the mode-keys option: copy-mode (emacs) or copy-mode-vi (vi). The default is emacs, unless the VISUAL or EDITOR environment variable contains "vi".

Copy-Pipe: Sending to System Clipboard

By default, tmux copies to its own internal paste buffers. To also send copied text to the system clipboard, use copy-pipe or copy-pipe-and-cancel: 

# In ~/.tmux.conf -- vi mode example: y copies to system clipboard
bind-key -T copy-mode-vi y send-keys -X copy-pipe-and-cancel "xclip -selection clipboard"

# macOS
bind-key -T copy-mode-vi y send-keys -X copy-pipe-and-cancel "pbcopy"

# Windows (WSL)
bind-key -T copy-mode-vi y send-keys -X copy-pipe-and-cancel "clip.exe"

Scrollback History

# Set scrollback buffer size (default is 2000 lines)
set -g history-limit 50000

# Clear history for the current pane
tmux clear-history
Note

The history-limit setting only applies to newly created windows. Existing windows retain whatever limit they had when they were created. Set this option early in your configuration file.

06 Mouse Support

tmux supports comprehensive mouse interaction, but it is off by default. When enabled, the mouse can be used for many common operations.

Enabling Mouse

# Enable mouse support (in ~/.tmux.conf or at command prompt)
set -g mouse on

What Mouse Support Enables

ActionWhat Happens

Click on window in status barSwitch to that window
Drag pane borderResize panes

Double-clickSelect a word
Triple-clickSelect a line
Right-clickContext menu (in newer versions) or paste

Mouse Events

When mouse is on, tmux captures mouse events and represents them as bindable keys. Each mouse event name is composed of an event type and a location suffix:

Event types: MouseDown1, MouseUp1, MouseDrag1, MouseDragEnd1, WheelUp, WheelDown, DoubleClick1, TripleClick1, SecondClick1 (also for buttons 2 and 3)

Location suffixes: Pane, Border, Status, StatusLeft, StatusRight, StatusDefault, ScrollbarSlider, ScrollbarUp, ScrollbarDown 

# Example: right-click on a pane to open a custom menu
bind-key -n MouseDown3Pane display-menu -T "Pane" ...

# Disable copy-on-drag but keep other mouse features
unbind -n MouseDrag1Pane
unbind -Tcopy-mode MouseDrag1Pane
Tip

To select text with your terminal's native selection (bypassing tmux) while mouse mode is on, hold Shift while clicking/dragging. This is useful for copying text to the system clipboard without configuring copy-pipe.

Scrollbars (tmux 3.6+)

tmux 3.6 introduced optional scrollbar support for panes: 

# Enable scrollbars
set -g pane-scrollbars on

# Set scrollbar position (left or right)
set -g pane-scrollbars-position right

07 Detach & Reattach -- The Killer Feature

The ability to detach and reattach is the defining feature of tmux. When you detach, the tmux server keeps all sessions, windows, panes, and their running programs alive in the background. When you reattach, everything is exactly as you left it.

Why This Matters

  • SSH resilience -- your remote work survives network drops, WiFi switches, laptop sleep
  • Long-running processes -- start a build, detach, go home, reattach from another machine
  • Context switching -- maintain multiple project environments, attach to whichever you need
  • Pair programming -- multiple people attach to the same session simultaneously

Detaching

# From inside tmux: prefix + d
Ctrl+B then d

# From the command line (detach a specific client)
tmux detach-client -t /dev/pts/1

# Detach all OTHER clients from the session
tmux detach-client -a

Reattaching

# Reattach to the most recent session
tmux attach
# or
tmux a

# Attach to a named session
tmux attach -t myproject

# Attach and detach all other clients (exclusive access)
tmux attach -dt myproject

# Create session if it doesn't exist, or attach if it does
tmux new-session -A -s myproject

Listing Sessions

# List all sessions
tmux list-sessions
# or
tmux ls

# Output example:
development: 3 windows (created Mon Mar 22 10:00:00 2026) (attached)
monitoring: 2 windows (created Mon Mar 22 09:30:00 2026)

Detach-on-Destroy Behavior

The detach-on-destroy option controls what happens when the attached session is destroyed:

  • on (default) -- detach the client
  • off -- switch to the most recently active remaining session
  • no-detached -- detach only if there are no detached sessions
  • previous / next -- switch to the previous/next session alphabetically
The Detach/Reattach Lifecycle: 1. Start 2. Work 3. Detach $ tmux new -s work --> [edit code, run --> Ctrl+B d tests, etc.] (or SSH drops) | v Server keeps running All processes alive | 5. Continue 4. Reattach | [everything is <-- $ tmux attach -t work <---+ exactly as (from any terminal, you left it] even different machine)

09 Status Bar

tmux displays an optional status line at the bottom of the terminal (one line by default, can be multiple lines or disabled entirely).

Default Status Bar Layout

[session-name] 0:bash 1:vim* 2:htop- "hostname" 15:30 22-Mar-26 | | | | session name window list pane title time/date Window flags: * current window - last window (previously selected) # activity detected (monitor-activity) ! bell occurred ~ silence detected (monitor-silence) M contains marked pane Z active pane is zoomed

Status Bar Options

# Turn status bar on/off
set -g status on       # on, off, or number of lines (2, 3, etc.)

# Position: top or bottom
set -g status-position bottom

# Refresh interval in seconds (default: 15)
set -g status-interval 5

# vi or emacs key bindings in command prompt
set -g status-keys vi

Customizing Left & Right Sections

# Left side (default: session name)
set -g status-left "[#S] "
set -g status-left-length 40

# Right side (default: pane title, date, time)
set -g status-right "#{pane_title} | %H:%M %d-%b-%y"
set -g status-right-length 60

10 Configuration (~/.tmux.conf)

tmux reads its configuration from these locations (in order):

  1. /etc/tmux.conf (system-wide, if present)
  2. ~/.tmux.conf (user, traditional location)
  3. $XDG_CONFIG_HOME/tmux/tmux.conf (user, XDG-compliant)

The config file is a set of tmux commands executed when the server first starts. You can reload it without restarting: 

# Reload config (from tmux command prompt: Prefix + :)
source-file ~/.tmux.conf

# Or bind a key to reload
bind r source-file ~/.tmux.conf \; display "Config reloaded!"

Recommended Starter Configuration

# ── General ──
set -g default-terminal "tmux-256color"       # proper terminal type
set -sa terminal-features ",xterm*:RGB"       # enable RGB color
set -g escape-time 10                        # reduce escape delay (ms)
set -g history-limit 50000                   # generous scrollback
set -g focus-events on                       # pass focus events to apps

# ── Prefix ──
set -g prefix C-a                            # change prefix to Ctrl+A
unbind C-b                                    # unbind default prefix
bind C-a send-prefix                          # press Ctrl+A twice to send literal

# ── Mouse ──
set -g mouse on                               # enable mouse support

# ── Windows ──
set -g base-index 1                           # start window numbering at 1
set -g renumber-windows on                    # renumber when a window is closed

# ── Panes ──
setw -g pane-base-index 1                     # start pane numbering at 1

# ── Vi mode ──
setw -g mode-keys vi                          # vi keys in copy mode
set -g status-keys vi                         # vi keys in command prompt

# ── Intuitive splits (use | and - instead of % and ") ──
bind | split-window -h -c "#{pane_current_path}"
bind - split-window -v -c "#{pane_current_path}"

# ── New windows in current directory ──
bind c new-window -c "#{pane_current_path}"

# ── Reload config ──
bind r source-file ~/.tmux.conf \; display "Config reloaded!"

# ── Status bar ──
set -g status-style "bg=#1c2333,fg=#8b949e"
set -g status-left "#[fg=#3fb950,bold] #S "
set -g status-right "%H:%M"
set -g window-status-current-style "underscore"

# ── Pane borders ──
set -g pane-border-style "fg=#30363d"
set -g pane-active-border-style "fg=#58a6ff"

11 Common Workflows

Development Setup

Create a project workspace with editor, terminal, and logs in one window.

# Script: dev-session.sh
tmux new-session -d -s dev -n editor
tmux send-keys -t dev:editor 'vim .' Enter

tmux split-window -h -t dev:editor
tmux send-keys 'npm run dev' Enter

tmux split-window -v -t dev:editor.2
tmux send-keys 'tail -f logs/app.log' Enter

tmux select-pane -t dev:editor.1
tmux attach -t dev

Remote Work with SSH

Keep your work alive across SSH disconnections and work from multiple machines.

# On remote server:
tmux new -s project

# ... work work work ...
# SSH drops or you detach

# Reconnect from anywhere:
ssh user@server
tmux attach -t project

# Or create-if-not-exists:
ssh user@server -t 'tmux new -A -s project'

Pair Programming

Multiple developers share a tmux session in real time, each seeing the same output.

# Developer 1 starts session:
tmux new -s pairing

# Developer 2 attaches to same session:
tmux attach -t pairing

# Both see the same windows/panes
# Both can type and interact

# For read-only access:
tmux attach -rt pairing

# Independent cursors (v3.1+):
tmux attach -t pairing \
  -f active-pane

Multi-Server Monitoring

Monitor multiple servers simultaneously with synchronized input.

# Create monitoring session
tmux new -s monitor -n servers

# Split into 4 panes
tmux split-window -h
tmux split-window -v
tmux select-pane -t 1
tmux split-window -v

# SSH into each server
tmux send-keys -t 1 'ssh web1' Enter
tmux send-keys -t 2 'ssh web2' Enter
tmux send-keys -t 3 'ssh db1' Enter
tmux send-keys -t 4 'ssh db2' Enter

# Synchronize input (type in all):
# Prefix + : then
setw synchronize-panes on

Background Builds

Start a long-running build, detach, come back later.

# Start build in tmux
tmux new -s build
make -j8 all

# Detach: Ctrl+B, d
# Go home, have dinner...

# Check back:
tmux attach -t build
# Build output is right there

# Or check without attaching:
tmux capture-pane -t build -p | tail

Session Scripting

Automate your entire workspace setup in a shell script.

#!/bin/bash
SESSION="myproject"

tmux has-session -t $SESSION 2>/dev/null
if [ $? != 0 ]; then
  tmux new -d -s $SESSION -n code
  tmux new-window -t $SESSION -n test
  tmux new-window -t $SESSION -n logs

  tmux send-keys -t $SESSION:code \
    'cd ~/project && vim' Enter
  tmux send-keys -t $SESSION:test \
    'cd ~/project' Enter
  tmux send-keys -t $SESSION:logs \
    'tail -f /var/log/app.log' Enter

  tmux select-window -t $SESSION:code
fi

tmux attach -t $SESSION

12 tmux vs GNU Screen

GNU Screen (1987) was the original terminal multiplexer. tmux (2007/2009) was created as a modern replacement. Here is how they compare:

License ISC (BSD-style) -- permissive GPL v3 -- copyleft
First release 2009 (OpenBSD 4.6) 1987
Active development Yes -- frequent releases, active GitHub Minimal -- mostly maintenance
Client-server model Clean separation -- server + client processes communicate via socket Single process model
Pane splits First-class: horizontal + vertical, any number of panes per window Vertical splits added later (v4.1), horizontal natively. Less flexible
Scripting Every action is a command; rich format variables; conditional config More limited scripting capabilities

Verdict

For virtually all modern use cases, tmux is the better choice. It has more features, better pane support, richer scripting, active development, and a permissive license. GNU Screen still has a niche for serial terminal connections and environments where only Screen is available. Many Linux distributions now include tmux by default.

Target Syntax

Many tmux commands accept -t target to specify which session, window, or pane to act on: 

# Target formats:
session          # target a session by name

# Examples:
dev              # session named "dev"
dev:2            # window 2 in session "dev"
dev:editor.1     # pane 1 of window "editor" in session "dev"
:2               # window 2 in the current session
:.1              # pane 1 in the current window

# Special tokens:

{previous}       # the previous pane/window
{mouse}          # the pane/window under the mouse (in mouse bindings)
{marked}         # the marked pane

14 Best Practices & Tips

Configuration Best Practices

  • Set escape-time low (e.g., 10ms) -- the default 500ms causes noticeable delay for vi/vim users after pressing Escape
  • Enable focus-events -- allows vim/neovim and other apps to detect when they gain or lose focus
  • Set default-terminal to "tmux-256color" -- ensures proper terminal capability detection
  • Enable renumber-windows -- prevents gaps in window numbering when windows are closed
  • Set base-index to 1 -- window/pane numbering starting at 1 matches keyboard layout (1 is easier to reach than 0)
  • Use #{pane_current_path} in split/new-window bindings to preserve the current directory
  • Set generous history-limit (50000+) -- memory is cheap, losing scrollback is frustrating

Workflow Tips

  • Name your sessions -- tmux new -s project-name instead of letting them be numbered
  • Name your windows -- Ctrl+B then , to rename; makes the status bar actually useful
  • Use zoom -- Ctrl+B then z to temporarily maximize a pane, press again to restore
  • Use the tree view -- Ctrl+B then w gives a visual overview of all sessions/windows/panes
  • Script your layouts -- create shell scripts that set up your project environment automatically
  • Use synchronize-panes -- for running the same command on multiple servers simultaneously
  • Use session groups for pair programming with independent window switching

Performance Tips

  • Reduce status-interval only if needed -- lower values mean more frequent redraws
  • Avoid overly complex status-right/left formats that call shell commands every refresh cycle
  • Use tmux-256color instead of screen-256color for better feature detection
  • Clear scrollback periodically for panes with heavy output: clear-history

Security Considerations

  • tmux creates sockets with permissions preventing access by other users by default
  • The server-access command can grant access to other users -- use with extreme caution
  • Read-only clients can still observe all session content -- do not share sessions with untrusted users
  • Sensitive data in scrollback history persists until cleared or the pane is destroyed

Common Pitfalls

Common Mistakes
  • Nested tmux: Running tmux inside tmux sends the prefix to the outer tmux. Press prefix twice (Ctrl+B Ctrl+B) to send it to the inner tmux, or use a different prefix for the inner session
  • $TERM misconfiguration: Always use tmux-256color or screen-256color -- never set $TERM to xterm-256color inside tmux (causes incorrect escape sequences)
  • Forgetting sessions: Run tmux ls regularly to check for orphaned sessions consuming resources
  • Colors look wrong: Usually a $TERM problem. Ensure your terminal emulator sets xterm-256color, and tmux sets tmux-256color
  • Config not loading: Remember tmux reads config only when the server starts (first session). Use source-file to reload

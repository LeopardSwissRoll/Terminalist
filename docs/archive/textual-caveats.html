01키 입력 함정

!
Ctrl+키 구분 불가 (레거시 모드)

레거시 터미널에서 Ctrl+H와 Backspace는 같은 바이트(\x08)를 생성합니다. Kitty 프로토콜 미지원 터미널(VSCode 등)에서는 이 키들을 구분할 수 없습니다.

바이트키 조합 1키 조합 2Textual 처리
\x08Ctrl+HBackspacebackspace
\x09Ctrl+ITabtab
\x0dCtrl+MEnterenter
\x1bCtrl+[Escapeescape
대응 전략

이 키들을 바인딩에 사용할 때는 "통일된 이름"만 사용하세요. key_ctrl_h() 핸들러를 정의하면 레거시 모드에서 Backspace에도 반응합니다.

!
KEY_NAME_REPLACEMENTS 암묵적 치환

on_key() 핸들러에서 event.key를 확인하면 이미 치환된 이름이 옵니다.

주의 필요
def on_key(self, event):
    if event.key == "ctrl+h":
        # ← 여기 안 들어옴!
        # "backspace"로 치환됨
        ...
올바른 방법
def on_key(self, event):
    if event.character == "\x08":
        # 원시 바이트로 확인
        ...
    if event.key == "backspace":
        # 치환된 이름으로 확인
        ...
!
ESC 키 100ms 딜레이

ESC를 누르면 XTermParser가 100ms 대기하며 이스케이프 시퀀스인지 판단합니다. 빠르게 ESC 후 다른 키를 누르면 잘못 해석될 수 있습니다.

# _xterm_parser.py — ESCAPE_DELAY = 0.1초
new_character = yield read1(ESCAPE_DELAY)
# 타임아웃 → 단독 ESC
# 추가 문자 → 시퀀스 조립 계속
Terminalist 영향

tmux-like prefix(Ctrl+B)와 ESC 딜레이가 겹치지 않도록 prefix 키는 ESC가 아닌 키를 사용하는 것이 안전합니다.

!
Windows ESC 이중 전송

Windows 콘솔이 ESC 한 번에 \x1b\x1b를 보내는 경우가 있습니다. Textual은 이를 단일 ESC로 처리하지만, 직접 ESC 시퀀스 파서를 만든다면 주의가 필요합니다.

# _ansi_sequences.py:51-53
"\x1b\x1b": (Keys.Escape,)  # 단일 ESC로 처리

02렌더링 함정

!
refresh()는 즉시 렌더링하지 않음

widget.refresh()를 호출해도 dirty 플래그만 설정됩니다. 실제 렌더링은 다음 Idle 이벤트에서 배치 처리됩니다.

함정
self.refresh()
print(self.size)
# ← 아직 이전 값!
올바른 패턴
self.refresh(layout=True)
# 다음 이벤트에서 size 사용
# 또는 recompose() await
!
call_from_thread는 App 레벨만

call_from_thread()는 App에만 존재합니다. Widget에는 없습니다.

에러
# Widget에는 없음!
self.call_from_thread(
    self.some_method
)
올바른 방법
# App 레벨 사용
self.app.call_from_thread(
    self.some_method
)
!
Strip은 불변(immutable)

Strip(렌더링된 한 줄)은 불변 객체입니다. 내부 Segment를 직접 수정하면 캐시가 무효화되지 않아 렌더링 버그가 발생합니다.

위험
strip._segments[0] = new_seg
# 캐시 무효화 안 됨!
안전
new_strip = Strip(new_segments)
# 새 Strip 생성
!
CJK 와이드 문자

한글 등 CJK 문자는 셀 2개를 차지합니다. 길이 계산에 len() 대신 cell_len()을 사용하세요.

from textual._cells import cell_len

len("안녕")       # → 2 (파이썬 문자 수)
cell_len("안녕")  # → 4 (터미널 셀 수 = 2글자 × 2셀)

03CSS 주의사항

!
TCSS ≠ 웹 CSS

Textual CSS는 웹 CSS의 서브셋입니다. 지원하지 않는 속성들:

지원 안 됨대안
floatdock 사용
position: absolute/fixedoverlay, dock 사용
flexboxlayout: horizontal/vertical + fr 단위
z-indexlayers 속성
animation, @keyframestransitions만 지원
@media 쿼리Python 코드에서 크기 체크
calc()지원 안 됨
!
인라인 CSS는 핫 리로드 안 됨

CSS_PATH로 지정한 외부 파일은 자동 감시 & 핫 리로드되지만, CSS 클래스 변수에 직접 쓴 인라인 CSS는 핫 리로드가 안 됩니다.

핫 리로드 안 됨
class MyApp(App):
    CSS = """
    Screen { background: red; }
    """
핫 리로드 가능
class MyApp(App):
    CSS_PATH = "my_app.tcss"

CSS 단위 참조표

단위의미예시
(숫자만)고정 셀 수width: 20
fr남은 공간 비율width: 2fr
%부모 대비 퍼센트width: 50%
w / h부모 너비/높이 %width: 50w
vw / vh뷰포트 너비/높이 %width: 100vw
auto자동 계산width: auto

04이벤트/메시지 함정

!
event.stop() 없이 키를 "소비"할 수 없음

Key 이벤트는 bubble=True입니다. event.stop()을 호출하지 않으면 부모로 전파됩니다.

키가 부모로 전파됨
def on_key(self, event):
    if event.key == "ctrl+b":
        self.do_something()
        # stop() 없음 → 부모도 받음
키를 소비
def on_key(self, event):
    if event.key == "ctrl+b":
        self.do_something()
        event.stop()  # ★ 전파 중단
!
key_ 핸들러와 on_key 둘 다 호출됨

key_ctrl_b()와 on_key()를 둘 다 정의하면 둘 다 호출됩니다.

class MyWidget(Widget):
    def key_ctrl_b(self, event):
        # 1. 이것이 먼저 호출됨
        self.enter_prefix()

    def on_key(self, event):
        # 2. 이것도 호출됨!
        # event.key를 확인해서 처리할지 결정해야 함
        self.send_to_pty(event)  # ← ctrl+b도 PTY로 감!
!
Reactive 워처에서 DOM 쿼리 실패

init=True인 reactive의 워처가 마운트 전에 호출되면 DOM 쿼리가 실패합니다.

마운트 전 에러
count = reactive(0, init=True)

def watch_count(self, new):
    self.query_one("#label")
    # ← Mount 전이면 에러!
안전한 패턴
count = reactive(0)

def on_mount(self):
    # DOM 준비 완료 후 초기화
    self.query_one("#label")
        .update(str(self.count))

버블링 참조표

이벤트버블링비고
Key, Mouse*버블위젯 → Screen → App
Focus, Blur안 함해당 위젯에만
Mount, Unmount안 함
Resize안 함
Idle안 함

05스레딩 주의

!
단일 이벤트 루프 — 직접 위젯 조작 금지

Textual은 단일 asyncio 이벤트 루프에서 동작합니다. 백그라운드 스레드에서 직접 위젯을 조작하면 레이스 컨디션이 발생합니다.

레이스 컨디션!
import threading

def bg_task():
    widget.update("new")
    # ← 위험! 다른 스레드!

threading.Thread(
    target=bg_task
).start()
안전한 방법
def bg_task():
    app.call_from_thread(
        widget.update, "new"
    )
    # ← 이벤트 루프로 전달

threading.Thread(
    target=bg_task
).start()
!
Worker 예외 → 앱 종료

@work(exit_on_error=True)가 기본값입니다. 워커에서 미처리 예외가 발생하면 앱 전체가 종료됩니다.

# 앱 종료 방지
@work(thread=True, exit_on_error=False)
async def risky_task(self):
    try:
        await dangerous_operation()
    except Exception:
        self.notify("에러 발생", severity="error")

06성능 함정

!
render()에 비싼 연산 넣지 말 것

render()는 위젯이 dirty할 때마다 호출됩니다. 파일 읽기, API 호출 등을 넣으면 성능이 급격히 저하됩니다.

render()에서 I/O
def render(self):
    with open("data.txt") as f:
        return f.read()
    # 매 리페인트마다 파일 읽기!
데이터를 reactive로
data = reactive("")

def load(self):
    with open("data.txt") as f:
        self.data = f.read()

def render(self):
    return self.data
!
메시지 큐 포화

대량 이벤트를 빠르게 post하면 큐가 쌓입니다. can_replace()를 구현하면 같은 타입의 이전 메시지를 대체할 수 있습니다.

class ScreenUpdate(Message):
    def can_replace(self, message):
        # 같은 타입의 이전 메시지를 대체
        return isinstance(message, ScreenUpdate)
팁: query() vs query_one()

query_one()은 내부적으로 캐시되지만 query()는 매번 탐색합니다. 반복적으로 같은 쿼리를 한다면 결과를 변수에 저장하세요.

07플랫폼별 이슈

Windows

ConPTY 충돌 가능성

pywinpty(PtyProcess)와 Textual 드라이버 모두 ConPTY를 사용합니다. 동시에 쓸 때 별도 콘솔 핸들을 사용해야 합니다.

  • UTF-16 서로게이트 페어 — 이모지 입력 시 encode("utf-16", "surrogatepass") 처리 필요 (이슈 #3178)
  • ANSI 색상 — ENABLE_VIRTUAL_TERMINAL_PROCESSING이 꺼져있으면 ANSI 이스케이프가 그대로 출력됨
  • 콘솔 크기 — WINDOW_BUFFER_SIZE_EVENT로 감지, ConPTY 경유 시 부정확할 수 있음

VSCode 통합 터미널

가장 주의해야 할 환경

VSCode 터미널은 xterm.js 기반으로, Kitty 프로토콜을 지원하지 않습니다.

  • Ctrl+K, Ctrl+Shift+P 등 VSCode 단축키가 터미널까지 안 내려옴
  • DA/XTVERSION 응답이 stdin에 섞일 수 있음
  • terminal.integrated.sendKeybindingsToShell 설정을 건드리면 Shift+Enter 등이 깨질 수 있음

tmux/screen 내부에서 실행 시

  • 이스케이프 시퀀스가 한 번 더 래핑됨
  • 마우스 이벤트 좌표가 변환될 수 있음
  • Kitty 프로토콜이 중간에서 필터링될 수 있음

08테스트 주의

!
HeadlessDriver는 실제 입력을 받지 않음

테스트용 HeadlessDriver는 pilot.press()/pilot.click()으로 시뮬레이션합니다. 실제 터미널 입력 경로(드라이버 → 파서)는 테스트되지 않습니다.

# pilot을 이용한 테스트
async with app.run_test() as pilot:
    await pilot.press("ctrl+a")  # Key 이벤트 직접 주입
    await pilot.click(MyWidget)  # 클릭 시뮬레이션
실전 조언

Windows 특유의 입력 이슈를 잡으려면 실제 터미널에서 수동 테스트가 필수입니다. CI에서는 SVG 스냅샷 테스트로 렌더링 회귀만 체크하세요.

01파일 구조 개요

Textual의 소스코드는 src/textual/ 아래에 약 80개 이상의 모듈로 구성됩니다. 핵심 모듈들을 기능별로 분류하면 다음과 같습니다.

Core

app.py / screen.py / widget.py

App, Screen, Widget — 앱의 3대 축. 이벤트 루프, 화면 컨테이너, 시각 요소를 담당합니다.

Message System

message.py / message_pump.py / events.py

모든 상호작용의 기반. 비동기 큐, 핸들러 디스패치, 이벤트 타입 정의.

DOM & Style

dom.py / css/ / reactive.py / binding.py

HTML DOM 유사 트리, TCSS 파싱/매칭/캐스케이딩, 반응형 속성, 키 바인딩.

Rendering

_compositor.py / strip.py / content.py / visual.py

화면 합성, Strip(불변 라인), 스타일 텍스트, 렌더링 프로토콜.

Input

_xterm_parser.py / _ansi_sequences.py / keys.py

터미널 입력 파싱, ANSI 시퀀스 매핑, Kitty 프로토콜, 키 이름 체계.

Drivers

drivers/windows_driver.py / linux_driver.py / ...

플랫폼별 I/O 추상화. Windows ConPTY, Linux termios, Web, Headless.

textual/ ├── app.py App 클래스 (진입점, 이벤트 루프) ├── driver.py Driver ABC (플랫폼 I/O 추상화) ├── screen.py Screen (위젯 컨테이너, 레이아웃) ├── widget.py Widget (시각 요소 베이스) ├── dom.py DOMNode (트리 구조 베이스) ├── message.py Message (이벤트/메시지 베이스) ├── message_pump.py MessagePump (비동기 메시지 큐) ├── events.py 내장 이벤트 타입들 ├── binding.py 키 바인딩 시스템 ├── reactive.py Reactive 디스크립터 ├── _compositor.py 화면 합성 엔진 ├── _xterm_parser.py 터미널 입력 파서 ├── _ansi_sequences.py ANSI 시퀀스 → 키 매핑 ├── _keyboard_protocol.py Kitty 프로토콜 키 정의 ├── _dispatch_key.py key_<name> 핸들러 디스패치 ├── keys.py Keys enum (키 이름 정의) │ ├── drivers/ 플랫폼별 드라이버 │ ├── windows_driver.py + win32.py (Windows ConPTY) │ ├── linux_driver.py (Linux/macOS) │ ├── web_driver.py (브라우저) │ └── headless_driver.py (테스트용) │ ├── css/ CSS 엔진 │ ├── parse.py / model.py / match.py │ ├── styles.py / stylesheet.py / scalar.py │ └── layouts/ 레이아웃 엔진 ├── vertical.py / horizontal.py / grid.py

02클래스 계층 구조

Textual의 모든 핵심 클래스는 하나의 뿌리에서 시작합니다: MessagePump.

MessagePump (비동기 메시지 큐 + 핸들러 디스패치) └── DOMNode (트리 구조 + CSS 스타일 + 키 바인딩) ├── App (이벤트 루프 + 드라이버 + 스타일시트) └── Widget (시각 렌더링 + 포커스 + 레이아웃) └── Screen (컴포지터 + 위젯 컨테이너 + 포커스 관리)
핵심 인사이트

App도 Widget도 결국 MessagePump를 상속합니다. 즉 모든 Textual 객체는 자신만의 메시지 큐를 돌리는 비동기 메시지 처리기입니다. 이 설계 덕분에 이벤트를 주입하는 것만으로 테스트가 가능합니다.

03MessagePump — Textual의 심장

모든 Textual 객체의 베이스. 비동기 메시지 큐를 운영하며, 핸들러를 자동 탐색해 디스패치합니다.

내부 상태

class MessagePump:
    _message_queue: Queue[Message]    # 대기 중인 메시지
    _task: asyncio.Task               # _process_messages_loop() 실행 태스크
    _timers: WeakSet[Timer]           # 활성 타이머들
    _next_callbacks: List              # 현재 메시지 처리 후 실행할 콜백
    _decorated_handlers: Dict          # @on() 데코레이터 핸들러 캐시

메시지 처리 루프

1. _process_messages_loop()
메인 비동기 루프. 큐에서 메시지를 하나씩 디큐합니다.
2. _dispatch_message(msg)
메시지를 적절한 핸들러로 라우팅합니다.
3. _get_dispatch_methods(name, msg)
MRO(Method Resolution Order)를 순회하며 핸들러를 탐색합니다.
4. Idle 이벤트 삽입
큐가 비면 Idle 이벤트를 삽입하여 렌더링을 트리거합니다.

핸들러 탐색 우선순위

순서
  1. @on() 데코레이터로 등록된 핸들러 (명시적)
  2. on_<message_name>() 네이밍 컨벤션 (암묵적)
  3. MRO 순서로 상위 클래스까지 탐색

실제 예시

from textual.app import App
from textual import events, on
from textual.widgets import Button

class MyApp(App):

    # 방법 1: 네이밍 컨벤션
    def on_key(self, event: events.Key):
        self.log(f"키 입력: {event.key}")

    # 방법 2: @on() 데코레이터 (셀렉터 지원)
    @on(Button.Pressed, "#submit")
    def handle_submit(self, event: Button.Pressed):
        self.log("제출 버튼 눌림!")

주요 메서드

메서드설명
post_message(msg)큐에 메시지 추가 (스레드 안전)
call_next(callback)현재 메시지 처리 완료 후 즉시 실행
call_later(callback)큐에 이벤트로 추가 (지연 실행)
set_timer(delay, cb)원샷 타이머
set_interval(interval, cb)반복 타이머
prevent(MsgType)컨텍스트 매니저: 특정 메시지 타입 억제

04DOMNode & Widget

DOMNode — 트리 구조

HTML DOM과 유사한 트리 구조. CSS 셀렉터 쿼리를 지원합니다.

class DOMNode(MessagePump):
    _nodes: NodeList        # 자식 노드들
    _id: str | None         # CSS ID (#id)
    _classes: set[str]      # CSS 클래스 (.class)
    _css_styles: Styles     # CSS에서 온 스타일
    _inline_styles: Styles  # 인라인 스타일
    styles: RenderStyles    # 병합된 최종 스타일
    _bindings: BindingsMap  # 키 바인딩

쿼리 예시

# CSS 셀렉터로 위젯 탐색
buttons = self.query("Button.primary")      # 여러 매치
header = self.query_one("#header", Header)   # 단일 매치 (캐시됨)
self.walk_children(method="dfs")               # 깊이 우선 순회

Widget — 시각 요소

화면에 그려지는 모든 요소의 베이스 클래스입니다.

class Widget(DOMNode):
    # Reactive 속성들
    can_focus: bool      # 포커스 가능 여부
    disabled: bool       # 비활성화
    loading: bool        # 로딩 상태

    # 크기/위치
    size: Size           # 현재 렌더링 크기 (width, height)
    virtual_size: Size   # 스크롤 가능한 전체 크기
    region: Region       # 화면 상 위치 (x, y, width, height)

05Screen & App

Screen — 위젯 컨테이너

위젯 트리의 최상위 컨테이너. 내부에 Compositor를 가지고 있어 레이아웃과 렌더링을 총괄합니다.

class Screen(Widget):
    _compositor: Compositor     # 레이아웃 & 렌더링 엔진
    _dirty_widgets: set         # 업데이트 필요한 위젯들
    focused: Widget | None      # 현재 포커스된 위젯
    maximized: Widget | None    # 최대화된 위젯
스크린 스택

스크린은 스택으로 관리됩니다. app.push_screen()으로 새 스크린을 쌓고, 활성 스크린은 항상 스택 최상위입니다. 모달 다이얼로그가 이 방식으로 구현됩니다.

App — 최상위 오케스트레이터

class App(DOMNode):
    console: Console           # Rich Console (출력)
    driver: Driver             # 플랫폼 I/O
    _screen_stack: list[Screen]  # 화면 스택
    stylesheet: Stylesheet     # CSS 스타일시트
    workers: WorkerManager     # 백그라운드 태스크
    focused: Widget | None     # 현재 포커스
    size: Size                 # 터미널 크기

App 실행 순서

1. 드라이버 생성 & start_application_mode()
플랫폼별 드라이버 초기화, alt screen 진입, 마우스 활성화
2. CSS 로드 & 파싱
DEFAULT_CSS + CSS + CSS_PATH 순서로 로드
3. Load → Compose → Resize → Mount
이벤트 시퀀스로 위젯 트리 구성 및 최초 레이아웃
4. _process_messages_loop() 진입
메인 이벤트 루프 시작 — 여기서부터 사용자 입력 처리

실제 App 예시

from textual.app import App, ComposeResult
from textual.widgets import Header, Footer, Static

class MyApp(App):
    CSS_PATH = "my_app.tcss"      # 외부 CSS 파일 (핫 리로드 지원)
    BINDINGS = [
        ("q", "quit", "종료"),
        ("ctrl+b", "prefix", "Prefix"),
    ]

    def compose(self) -> ComposeResult:
        yield Header()
        yield Static("Hello, Textual!", id="main")
        yield Footer()

    def on_mount(self):
        self.log("앱이 마운트되었습니다.")

if __name__ == "__main__":
    MyApp().run()

06드라이버 시스템

드라이버는 플랫폼 I/O를 추상화합니다. 입력 읽기, 출력 쓰기, 터미널 모드 전환을 담당합니다.

Driver ABC

class Driver(ABC):
    def write(data: str)              # 터미널에 쓰기
    def flush()                       # 출력 버퍼 플러시
    def start_application_mode()      # raw 모드 진입
    def stop_application_mode()       # 원래 모드 복원
    def disable_input()               # 입력 읽기 중단
    def process_message(msg)          # 메시지 전처리 (좌표 조정 등)

드라이버 종류

드라이버 파일 용도
WindowsDriver windows_driver.py + win32.py Windows ConPTY. ReadConsoleInputW로 입력 읽기.
LinuxDriver linux_driver.py Linux/macOS. os.read(stdin)으로 입력 읽기.
WebDriver web_driver.py 브라우저 기반 렌더링. WebSocket 통신.
HeadlessDriver headless_driver.py 테스트용. 80×25 고정 크기, I/O 없음.

Windows 드라이버 초기화 — 핵심 코드

# windows_driver.py:86-106
def start_application_mode(self):
    self._restore_console = win32.enable_application_mode()

    self.write("\x1b[?1049h")   # Alt screen 활성화
    self._enable_mouse_support()
    self.write("\x1b[?25l")     # 커서 숨김
    self.write("\033[?1004h")   # FocusIn/FocusOut 활성화
    self.write("\x1b[>1u")      # ★ Kitty 키보드 프로토콜 활성화
    self._enable_bracketed_paste()
주의: Win32 콘솔 모드

win32.py:179에서 stdin을 ENABLE_VIRTUAL_TERMINAL_INPUT (0x0200)으로 설정합니다. 이때 기존 모드를 OR 하지 않고 대입하므로 ENABLE_PROCESSED_INPUT 등이 꺼집니다. 이것은 의도된 동작(raw 모드)이지만, Terminalist처럼 PTY를 호스팅하는 앱에서는 주의가 필요합니다.

08CSS 엔진 (TCSS)

Textual은 TCSS (Textual CSS)를 사용합니다. 웹 CSS의 서브셋으로, 터미널 환경에 맞게 조정되었습니다.

처리 흐름

1. 토크나이징
CSS 텍스트 → 토큰 스트림 (셀렉터, 속성, 값)
2. 파싱
토큰 → RuleSet (SelectorSet + Styles)
3. 매칭
각 셀렉터를 DOM 노드에 매칭 (descendant, child, same 콤비네이터)
4. 캐스케이딩
특이성(specificity) 기반 스타일 병합. 인라인 > ID > 클래스 > 요소.
5. 적용
최종 계산된 스타일을 위젯에 적용

특이성 (Specificity) 예시

셀렉터특이성 (ID, Class, Element)
#submit(1, 0, 1)
Button.primary(0, 1, 1)
Button:hover(0, 1, 1)
Screen > Button(0, 0, 2)

09Reactive & Worker

Reactive 디스크립터

값이 바뀌면 자동으로 리페인트/레이아웃을 트리거하는 파이썬 디스크립터입니다.

from textual.reactive import reactive

class Counter(Widget):
    count = reactive(0)                # 변경 시 자동 리페인트
    title = reactive("", layout=True)  # 변경 시 레이아웃도 재계산

    def watch_count(self, old: int, new: int):
        # 워처: count가 바뀔 때마다 자동 호출
        self.log(f"카운트: {old} → {new}")

    def render(self):
        return f"Count: {self.count}"
옵션기본값설명
repaintTrue변경 시 위젯 리페인트
layoutFalse변경 시 부모 레이아웃 재계산
initFalse마운트 시 워처 호출
recomposeFalse자식 위젯 재구성

Worker 시스템

비동기 또는 스레드 기반 백그라운드 작업을 관리합니다.

from textual.worker import work

class MyWidget(Widget):

    @work(thread=True, exit_on_error=False)
    async def fetch_data(self):
        # 별도 스레드에서 실행됨
        result = await heavy_io_operation()
        # UI 업데이트는 반드시 call_from_thread 사용!
        self.app.call_from_thread(self.update_display, result)
주의

call_from_thread()는 App 레벨에만 존재합니다. Widget에는 없으므로 반드시 self.app.call_from_thread()를 사용하세요.

버블링 이해하기

bubble=True인 이벤트(Key, Mouse 등)는 포커스된 위젯 → 부모 위젯 → ... → Screen → App 순서로 전파됩니다. event.stop()을 호출하면 전파가 중단됩니다.

이벤트 핸들링 예시

class TerminalPane(Widget):
    def on_key(self, event: events.Key):
        if event.key == "ctrl+b":
            # prefix 키 가로채기
            self.enter_prefix_mode()
            event.stop()     # ★ 버블링 중단!
            return

        # 나머지 키는 PTY로 전달
        self.send_to_pty(event)

11핵심 설계 패턴

1

메시지 드리븐

모든 상호작용이 Message. 테스트에서 모킹 없이 메시지만 주입하면 됨.

2

합성 패턴 (Composite)

DOMNode 트리로 App → Screen → Widget 계층 구성. CSS 셀렉터로 쿼리.

3

리액티브 프로그래밍

Reactive 디스크립터로 값 변경 → 자동 리페인트/레이아웃. 수동 갱신 불필요.

4

관심사 분리

Driver(I/O) / MessagePump(라우팅) / Widget(렌더링) / Compositor(합성) 분리.

5

지연 평가

dirty 플래그 기반. 여러 refresh() → 한 번의 렌더링. 불필요한 렌더 방지.

6

불변 캐싱

Strip, Styles는 불변(immutable). 공격적 캐싱으로 성능 확보.

7

스레드 안전

단일 asyncio 이벤트 루프. 백그라운드 스레드는 call_from_thread()로 진입.
